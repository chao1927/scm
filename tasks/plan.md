## 4. Agent 领取协议

1. 协调 Agent 在 `todo.md` 将任务从 `[ ]` 改为 `[-]`，填写唯一 Agent 名称和领取时间。
2. Agent 只能修改任务规格声明的文件；共享契约或父 POM 变更交给协调 Agent。
3. 同一服务、Flyway 目录或前端子系统资源文件不得被两个 Agent 同时领取。
4. Agent 完成任务级测试后提交交接摘要；协调 Agent 合并日志并执行批次全量回归。
5. 任务只有代码、迁移、接口、事件、测试、文档和日志均满足时才能改为 `[x]`。

## 5. 风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 前端配置仍集中在两个文件 | 多 Agent 冲突 | P0 先执行 `PAR-NEXT-001` |
| 跨系统接口两边同时变化 | 契约漂移 | 先冻结命令/事件/幂等/错误码，再并行实现 |
| 同一服务多任务并发 | Flyway、Mapper、配置冲突 | 同一 Agent lane 内顺序执行 |
| 外部环境缺失 | 无法完成真实联调和上线验收 | 保持阻塞，不用模拟结果冒充 |
| 首轮完成被误认为生产完成 | 遗漏可靠性/运维工作 | 开发总纲明确区分仓库完成和生产完成 |
| HTTP/日志适配器冒充消息链路 | 事件未经过 Broker、无法可靠重试 | 九系统强制 Outbox→RocketMQ→Inbox；Noop/内存/日志仅允许测试 |
