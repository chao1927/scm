# 多版本代码收敛审计

## 1. 审计目标

本次审计针对开发过程中“新实现已上线，旧入口、旧构造方式或旧配置仍留在生产代码”的情况。判定依据是生产调用链、Spring 装配、RocketMQ/Dubbo 入口、前端资源引用、Git 演进记录和自动化测试，不仅根据类名判断。

## 2. 已收敛项

| 范围 | 发现的多版本问题 | 收敛结果 |
| --- | --- | --- |
| 中央库存 | `InventoryEventApplicationService` 同时保留旧发布门面和新 Outbox 投递调度，其 `publish` 无生产调用 | 删除兼容门面，改为单一 `InventoryOutboxOperationsApplicationService`；业务发布只依赖 `InventoryEventPublisher` |
| WMS/公共模块 | WMS 自建 Jackson 2 Bean，公共安全配置又定义同类 Bean | 删除 WMS 重复配置，九服务统一使用 `scmJackson2ObjectMapper` |
| MDM OpenAPI | 旧的三参数验签默认签署 `legacy` 操作，与当前按操作和载荷签名的入口并存；两个短构造器仅服务旧测试 | 删除旧验证入口和测试专用生产构造器，测试改用完整依赖和正式 `MASTER_DATA_SNAPSHOT` 签名协议 |
| 采购 | `CommandContext` 旧构造器会用 requestId/idempotencyKey 自动伪造请求摘要，与当前基于请求体的摘要并存 | 删除旧构造器；HTTP 继续使用实际请求摘要，RocketMQ 通过 `forEvent` 使用事件载荷摘要，可检出同编码不同内容的错误重放 |
| BMS | 退款快照、退款请求和支付回调同时保留旧短构造方式；旧 HTTP 回调未传递金额、币种、商户和支付流水事实；还有一个无调用的旧快照转换方法 | 删除三组旧构造器和死方法；支付回调按当前完整回执事实传递，避免新聚合校验被旧 DTO 截断 |
| 前端九系统 | 新 pageId 与旧原型菜单键长期并存，且 `records`/`stocks`/供应商质量等旧键可同时命中多个新页面 | 删除 9 个系统的 `legacy` 配置和布局兼容分支，菜单只支持 `system-page`、`system.page`、`page` 正式键；测试锁定不再回归旧字段 |
| 前端权限 | `menuPermissions` 作为公开导出存在，实际只在模块内使用 | 收窄为模块私有常量，减少虚假公开 API |

## 3. 审计后保留的类型

| 类型 | 保留原因 |
| --- | --- |
| URL 中的 `/v1` | 这是当前对外接口版本，不是并存的代码实现 |
| 领域对象的 `version` 和“拒绝旧版本”规则 | 用于乐观锁、事件顺序和防止旧事实覆盖新事实，属于必需业务不变量 |
| Jackson 2 对象映射器 | RocketMQ 事件适配器仍使用 `com.fasterxml.jackson` 类型，与 Spring Boot 4 的 Jackson 3 可并存；已收敛为公共唯一 Bean |
| Outbox 手工派发和失败重放 HTTP 运维入口 | 入口只触发真实 RocketMQ 投递，不直接消费业务事件，不违反 RocketMQ-only 约束 |
| WMS 入出库、库存预占等 OpenAPI 命令 | 这些是明确的同步业务命令，不是 HTTP 事件消费入口，且仍在正式需求中 |

## 4. 验证证据

- JDK 17：后端 11 个 Maven 模块离线 `clean test` 成功，459 项测试无失败/错误，4 项真实 MySQL 条件测试按环境跳过。
- 前端：Vitest 43/43 通过，Vite 生产构建成功，共转换 4953 个模块。
- 消息架构：`project/qa/test-rocketmq-only-messaging.sh` 通过，九服务跨上下文业务事件仍仅通过 RocketMQ 生产和消费。

## 5. 运行注意事项

前端已不再解析旧原型菜单键。IAM 现存菜单数据如仍使用 `billingSubjects`、`records`、`stocks`、`supplier-order` 等旧编码，应在下次启动前通过 IAM 菜单管理重建为当前 `system-page` 或 `system.page` 编码。由于部分旧编码对应多个新页面，不应自动一对一迁移。
