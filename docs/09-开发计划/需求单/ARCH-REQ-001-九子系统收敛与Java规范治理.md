# ARCH-REQ-001 九子系统收敛与 Java 规范治理

> 状态：已完成。完成证据见 `docs/09-开发计划/00-供应链系统开发总纲.md` 的“交付证据台账”。

## 1. 目标

将可部署后端严格收敛为供应商、采购、WMS、中央库存、OMS、TMS、BMS、主数据、权限九个子系统，并保留 `scm-common` 公共/base 模块。按 JDK 17 和阿里 Java 编码规范治理全部 Java 源码，补齐可维护的业务注释和自动检查入口。

## 2. 边界决策

| 原模块 | 处理方式 | 业务理由 |
| --- | --- | --- |
| `integration-service` | 删除独立部署；可靠投递、Inbox/Outbox、重试、熔断、失败查询和重放归属命令发起方或事实接收方 | 集成不是独立业务事实源；集中路由会削弱限界上下文自治，并形成第十个业务服务 |
| `report-service` | 删除独立部署；履约指标归 OMS、库存指标归中央库存、费用/结算指标归 BMS、供应商绩效归供应商系统 | 指标口径和数据权限应由事实拥有者维护，避免复制四套事实形成口径漂移 |
| 前端集成/统一报表入口 | 删除；运维入口和报表入口进入对应子系统 | 用户按业务责任处理失败和查看报表，比跨域平台页更易理解、权限也更清晰 |
| `scm-common` | 保留 | 仅承载 API 信封、安全上下文、错误码、跨上下文发布契约等稳定公共类型，不拥有业务状态 |

## 3. 集成能力迁移

1. 供应商系统继续使用自身集成命令表、Dubbo 防腐层、按目标系统熔断和失败重放。
2. 采购系统继续拥有 `purchase_integration_command`，但不再二次投递到统一集成中心；命令类型到目标 URL 的映射从 Nacos 的 `scm.integration.routes.*.url` 读取。
3. WMS、中央库存、BMS 等接收方继续使用各自 Inbox 和内部/OpenAPI 契约执行幂等消费。
4. 未配置路由时必须失败关闭，命令进入采购最终失败治理，不允许伪造成功。
5. 真实 RocketMQ/Dubbo/HTTP 契约仍由生产者与消费者双方共同维护，不引入中心化数据库。

## 4. 报表能力归属

| 指标/报表 | 归属系统 | 现有入口 |
| --- | --- | --- |
| 订单履约、取消、售后 | OMS | OMS 工作台、销售订单与履约读模型 |
| 库存余额、流水、快照、对账 | 中央库存 | 库存查询、快照、对账页面 |
| 费用、账单、结算汇总 | BMS | `GET /api/bms/v1/reports/settlement-summary` 与结算报表页面 |
| 供应商绩效、质量、交付 | 供应商系统 | 供应商评分与运营页面 |

## 5. Java 规范与注释验收

- 编译版本固定为 JDK 17，禁止 Java 18+ API 和语法。
- 使用阿里 P3C 规则集执行自动检查；无本地可用规则时保留明确的降级说明，不能把普通编译冒充 P3C 检查。
- 所有 Java 类型具有职责、所属层次和边界说明。
- 所有显式字段、构造器和方法具有语义注释；命令、状态迁移、幂等、补偿、并发和外部调用必须说明业务原因。
- 全部压缩单行 Java 文件恢复为正常多行格式。
- 九子系统与 `scm-common` 全量编译、测试通过；前端测试和构建通过；启动脚本只启动九个 Java 服务。
