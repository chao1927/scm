# FE-REQ-009 完整业务菜单、登录态与 IAM 动态权限联调

## 1. 背景

前端已具备核心运营页面和本地菜单权限纯函数，但供应商采购订单确认、质量整改仍被硬编码禁用，未登录状态默认放行全部菜单，权限码来自浏览器存储而非 IAM 事实源。

## 2. 目标

- 接入 IAM 登录、当前用户、权限快照、应用菜单和退出接口。
- 已认证会话始终执行权限判断，空权限默认拒绝，不再使用开发态放行。
- 启用供应商采购订单确认和质量整改菜单，接入供应商真实查询及状态推进接口。
- 通过单元、构建和真实浏览器 E2E 验证。

## 3. 功能范围

| 范围 | 实现 |
| --- | --- |
| 会话 | IAM 用户名/密码登录；Token 仅保存会话；刷新页面重新读取 `/me`、权限快照和菜单 |
| 动态权限 | 从 `GET /openapi/iam/v1/users/me/permissions` 读取 `permissionPayload`，按通配符与精确权限控制叶子菜单 |
| 动态菜单 | 从 `GET /api/iam/v1/menus?appCode=SCM_WEB` 读取启用菜单、名称和排序；空配置保留静态引导菜单 |
| 订单确认 | 查询确认单，支持按原数量/交期确认、反馈差异和拒绝 |
| 质量整改 | 查询问题单，支持发起整改、提交方案、验证通过和退回整改 |
| 退出 | 调用 IAM logout，清除访问/刷新令牌并返回登录页 |

## 4. 权限与接口

| 菜单 | 权限 |
| --- | --- |
| ASN 发货通知 | `supplier:asn:read` |
| 采购订单确认 | `supplier:po_confirm:read` |
| 质量整改 | `supplier:quality:read` |

前端权限仅用于导航和交互提示，后端 JWT、业务权限和数据范围校验仍为安全事实边界。供应商写操作沿用请求 ID、Trace ID、组织头和幂等键拦截器。

## 5. 验收结果

- `npm run test`：2 个测试文件、8 项测试通过。
- `npm run build`：Vite 生产构建通过，供应商协同和登录页保持懒加载。
- `npm run test:e2e`：Chromium 2 项通过，覆盖真实 IAM 接口契约下的登录、动态菜单、供应商菜单启用和无权限禁用。
- `git diff --check -- project/frontend`：通过。

## 6. 已知限制

- IAM 数据库需预先配置 `SCM_WEB` 应用、菜单、用户角色和权限资源；空菜单配置只用于首次部署引导。
- 完整 OAuth/OIDC 授权码流、MFA 和生产密钥轮换不属于本需求单。
