# FE-REQ-010 九大子系统标准工作台、列表、详情前端重构

状态：已完成（2026-07-28）

## 1. 目标

依据 `docs/04-子系统功能设计` 和已确认原型，将供应商、采购、WMS、中央库存、OMS、TMS、BMS、MDM、IAM 九个子系统统一重构为“工作台 → 业务列表 → 业务详情”的正式 React 前端。

## 2. 实施原则

- 复用现有 React、Ant Design、TanStack Query、Axios、IAM 登录、动态菜单、权限判断、API 客户端和业务状态操作。
- 原型仅作为信息架构和视觉来源，不将演示数据、内存状态或原生 DOM 渲染搬入正式前端。
- 优先连接已有真实接口；缺少后端读模型的页面显示明确的能力缺口，不伪造业务数据。
- 每个业务页面具有可刷新、可收藏的独立 URL，查询、状态和分页进入 URL 参数。
- 前端权限只负责可见性和操作提示，后端鉴权与数据范围仍是安全事实源。

## 3. 实施范围

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| FE10-01 | React Router、统一应用壳、系统/模块导航 | 登录态、动态权限和页面懒加载保持可用 |
| FE10-02 | 公共工作台、查询列表、详情、状态、命令组件 | 加载、空数据、错误、权限和响应式状态完整 |
| FE10-03 | 采购系统完整样板 | 请购、RFQ、PO、到货、确认差异和失败事件可用 |
| FE10-04 | 供应商、WMS、中央库存 | 复用现有真实查询与状态推进能力 |
| FE10-05 | OMS、TMS、BMS | 拆分原聚合运营页面，形成独立路由 |
| FE10-06 | MDM、IAM | 拆分原管理页面，保留登录与动态权限 |
| FE10-07 | 集成中心、报表适配及旧页面清理 | 新框架内行为不回退，无失效旧入口 |
| FE10-08 | 单元、构建、E2E、响应式验收 | 320/768/1024/1440 可用，控制台无错误 |

## 4. 路由约定

```text
/:system/workbench
/:system/:page
/:system/:page/:recordId
```

筛选、状态、分页使用查询参数，例如：

```text
/purchase/orders?status=4&pageNo=1&keyword=PO2026
```

## 5. 完成标准

- 九个子系统均有工作台、业务菜单和独立路由。
- 已有真实接口均保留并迁移到相应列表或详情页面。
- 业务写操作保留幂等键、版本号、原因和确认。
- 登录、动态菜单、功能权限和数据范围行为不回退。
- `npm run test`、`npm run build`、`npm run test:e2e`、`git diff --check` 通过。
- 完成内容、删除项、接口缺口和风险同步记录到开发日志。

## 6. 非目标

- 不在前端伪造后端尚未提供的业务事实。
- 不修改九大子系统的领域状态机和接口语义。
- 不在本需求中重写后端接口或数据库。

## 7. 实施结果

- 九个子系统均已接入统一双层导航、子系统工作台、独立列表和独立详情路由。
- 采购、供应商、中央库存、OMS、TMS、BMS、MDM、IAM 及 WMS 运维已有读接口均已接入；无后端读模型的页面使用明确能力缺口页。
- 保留 IAM 登录、权限快照、菜单名称/顺序覆盖，并补齐子系统、集成中心和报表直达路由保护。
- 旧 ASN、采购、仓储库存、履约结算、MDM/IAM、供应商协同聚合页已删除。
- Vitest 14 项、Vite 生产构建及 Chromium E2E 4 项通过；浏览器覆盖核心链路、IAM 权限、320/768/1024/1440，并以 `console error`、`pageerror` 零记录作为验收门禁。
