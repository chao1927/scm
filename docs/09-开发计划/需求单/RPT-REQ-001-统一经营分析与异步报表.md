# RPT-REQ-001 统一经营分析与异步报表

> 历史需求：独立报表服务已由 `ARCH-REQ-001` 撤销。履约、库存、结算成本和供应商绩效分别归 OMS、中央库存、BMS 和供应商系统维护，本文仅保留原分析口径。

## 1. 目标

建立跨履约、库存、成本和供应商绩效的统一经营分析读模型，并提供受数据权限保护的异步 CSV 导出闭环。

## 2. 业务口径

| 指标域 | 核心指标 | 事实来源 |
| --- | --- | --- |
| 履约 | 订单量、已完成量、取消量、履约率、平均履约时长 | OMS 履约事实 |
| 库存 | 实物量、可用量、预占量、冻结量、库存准确率 | 中央库存余额/快照/对账事实 |
| 成本 | 应计金额、已结金额、退款金额、待结金额 | BMS 费用/账单/退款事实 |
| 供应商绩效 | 准时交付率、质量合格率、平均评分、整改关闭率 | 供应商/TMS/WMS 绩效事实 |

## 3. 领域与接口

- 报表上下文只拥有分析投影和导出任务，不反向修改业务聚合。
- 事件入口通过 Inbox 幂等写入指标事实，指标查询按组织、货主、仓库、供应商数据范围过滤。
- `GET /api/report/v1/metrics/{domain}` 查询指标。
- `POST /api/report/v1/exports` 创建异步导出，要求幂等键。
- `GET /api/report/v1/exports/{exportNo}` 查询状态。
- `GET /api/report/v1/exports/{exportNo}/download` 下载完成的 CSV。
- `POST /internal/report/v1/events` 消费标准业务事实。

## 4. 不变量与可靠性

- 同一 `sourceSystem + eventCode` 只能入账一次。
- 指标事实保留来源、业务时间、维度和版本，禁止只覆盖总数而无法追溯。
- 导出只能读取请求人有权访问的数据范围；任务归属不可越权查询或下载。
- 导出状态为 `PENDING -> RUNNING -> COMPLETED/FAILED`，失败可安全重试。
- 导出创建、状态事件和 Outbox 同事务；事件消费使用 Inbox。

## 5. 验收

- 四类指标口径、查询接口、数据权限、异步导出、持久化迁移、Outbox/Inbox 完成。
- 领域、应用、Web/API、幂等、越权和失败重试测试通过。
- 后端全量测试、前端构建和开发日志同步通过。
