# SUP-REQ-001 供应商核心业务需求基线

> 状态：已完成（仓库阶段）。2026-08-06 已完成 `SUP-API-001~008` 双向追踪与核心异常回归；真实 MySQL、RocketMQ 和跨进程 RPC 由 `QA-NEXT-001` 继续环境验收。

## 1. 业务目标

建立从供应商准入、资质、供货关系到订单协同、质量整改、绩效风险和财务协同的可信供应商闭环。

## 2. 范围与聚合

| 能力 | 核心聚合/读模型 | 关键不变量 |
| --- | --- | --- |
| 准入与档案变更 | 供应商、准入申请、档案变更 | 未通过准入不得启用；关键资料变更保留版本和审批 |
| 资质与供货条件 | 供应商资质、供应商商品 | 资质过期或冻结时禁止新增采购引用 |
| 报价、协议和合同 | 报价、价格协议、合同 | 报价受 RFQ 截标约束；有效期和适用范围不得冲突 |
| PO 与 ASN 协同 | PO 确认、ASN | 确认数量/交期可追踪；ASN 累计量不得超过可通知量 |
| 质量、整改和风险 | 质量问题、整改、评分 | 评分事实可追溯；严重/逾期问题触发风险升级 |
| 退供与财务协同 | 退供应商单、对账确认 | 退供数量不超可退量；对账差异未处理不得确认 |

## 3. 跨上下文规则

- 主数据拥有正式供应商档案发布版本；供应商上下文拥有协同、资质业务规则、供货能力和绩效风险事实。
- 采购拥有 RFQ、PO 主状态；供应商上下文只确认或反馈差异。
- WMS/TMS/BMS 分别拥有仓储、运输和结算事实，供应商只保留必要快照和待办。

## 4. 验收

- `SUP-API-001~008` 均可映射到本需求的聚合、不变量、事件、权限和测试。
- 准入、资质到期、冻结、PO 差异、ASN 重复、整改逾期、对账差异具有异常与补偿测试。
- 组织、供应商、货主和单据归属数据范围生效。

- 新增资质过期、供应商冻结命令、PO 行差异、ASN 重复提交、整改逾期、对账差异回归；原有准入、供货、报价、合同、退供、评分、幂等、导出、Web 权限与 RocketMQ 契约测试继续通过。
